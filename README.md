# wifi_tool — TUI для подбора пароля WiFi (Windows)

Приложение сканирует сети, читает ключи, которые Windows уже хранит, захватывает
PMKID/EAPOL-рукопожатие, конвертирует захват в формат hashcat mode 22000 и
подбирает пароль по словарю — всё в одном терминальном интерфейсе на
[opentui](https://github.com/anomalyco/opentui).

> Используйте только для сетей, к которым у вас есть разрешение.

---

## Что происходит по нажатию

**Enter** на выбранной сети открывает отчёт, **Enter** на отчёте запускает подбор.
Дальше программа сама делает всё, что на этой машине возможно, и останавливается
на первом успехе:

| # | Этап | Что проверяется | Размер |
|---|---|---|---|
| 1 | ключ Windows | сохранённый профиль этой сети | мгновенно |
| 2 | захват | PMKID или рукопожатие | до 60 с |
| 3 | кандидаты по имени и MAC | SSID, MAC и заводские пароли + цифры | ~80 тыс. |
| 4 | частые пароли | probable-wpa.txt | 4 800 |
| 5 | RockYou WPA | 
ockyou-wpa.txt | 9,6 млн |
| 6 | RockYou + мутации | est66.rule | ~620 млн |
| 7–8 | цифры 8–9 | маски ?d… | 10⁸ / 10⁹ |

Этапы идут по убыванию вероятности на секунду работы, первый успех останавливает
цепочку. План печатается в журнал до старта, **Esc** открывает окно остановки. План также
показан на экране аудита — до того, как что-то запущено.

Проверено на этой машине, без единой подмены: **A** сохранённый ключ
iPhone untitled — 	nyz4107, 0,13 с, метод: ключ Windows (_test_smoke.py).

### Про «шансы ближе к 100 %»

Прямо сказать стоит: метода, дающего 100 %, у WPA2 нет и быть не может — это
следствие самого алгоритма PBKDF2, а не недоработки программы. Данных, взятых из
одного имени сети, недостаточно в принципе: SSID, BSSID и канал выбирают цель,
но не содержат ничего, что проверяет пароль.

Поэтому «максимальная надёжность» здесь означает три конкретные вещи:

1. **Верный источник данных.** Захватываются и PMKID, и рукопожатие; извлечение
   ведётся через wpawolf, а встроенный конвертер — побайтово с ним совпадает
   (см. _test_groundtruth.py). Плохая конвертация ломает подбор чаще, чем плохой
   словарь.
2. **Проверка того, что не нужно угадывать.** Ключ из сохранённого профиля — единственный
   шаг, который не зависит от того, угадали мы или нет. Он идёт первым, и для сети,
   к которой этот компьютер когда-либо подключался, результат получается
   мгновенно и гарантированно.
3. **Правильный порядок кандидатов.** Пароли домашних роутеров гораздо чаще
   приходят из SSID, MAC-адреса, заводских настроек или мутаций известного слова,
   чем из утечки. Этап 3 (SSID/MAC/заводские + цифры) закрывает эту группу за
   доли секунды, а не после часа по rockyou.

Чего автоматика сделать не может: если пароль — случайная строка из 16 символов,
её нет ни в одном из этих этапов, и результат будет «не найден». Для своих сетей
с таким паролем это правильный ответ, а не неудача.

## Управление

Основной маршрут: **Сети → Проверка сети → Параметры → Выполнение → Результат**.
Все экраны используют один графитовый интерфейс: заголовок с контекстом,
рабочую область и актуальные клавиши внизу. На главной и в выборе файла
отдельного блока «Действия» нет; на остальных экранах он сохранён. На широком терминале
детали сети и пояснения параметров располагаются рядом с рабочей областью.

**F1** открывает меню команд с клавиатуры, отдельной кнопки внизу нет.
При подключённом M5StickC команда **«Захваты с платы»** читает сохранённые
файлы со стика, показывает число пар EAPOL и PMKID и обновляет копии в `captures`.
Выбор файла открывает сведения о захвате; **«Открыть параметры»** подставляет его
в форму. Выбор сети и новый захват для просмотра этих файлов не требуются.
Ввод фильтрует команды, **↑ ↓** выбирают действие,
**Enter** выполняет его, **Esc** закрывает окно с возвращением прежнего фокуса.
Недоступные действия имеют маркер **×** и приглушённый цвет. Диалог полностью получает
клавиатуру и вставку; команды под ним не запускаются.

Действия сгруппированы в основном порядке: основные команды, список и поиск,
источники данных, настройки, компоненты, сведения, переходы, приложение.
Частые команды стоят первыми внутри группы; возврат и выход находятся в конце.
Группировка задаёт только порядок: заголовков «Действия», подписей групп
и пояснений под командами нет. Tab и стрелки проходят только по командам.

Списки, меню и журнал прокручиваются коротким переходом с замедлением,
подсветка строк мягко меняется при выборе. Повторные нажатия сразу меняют цель,
Enter работает без ожидания анимации. Большие переходы Home/End и изменение
размера происходят сразу. Тонкая полоса показывает положение в длинном списке.
Для отключения движения можно задать `WIFI_TOOL_REDUCED_MOTION=1` перед запуском.

| Клавиши | Действие |
|---|---|
| **Tab / Shift+Tab** | следующий / предыдущий элемент или область; недоступные действия пропускаются |
| **↑ ↓** | строки активного списка, поля формы, действия или журнал |
| **Enter** | открыть выбранную сеть или выполнить выделенное действие |
| **Esc** | закрыть верхнее окно или вернуться назад; на главном экране открыть меню |
| **F1** | меню команд текущего экрана |
| **PageUp / PageDown** | страница активного списка, документа, меню или журнала |
| **Home / End** | начало / конец списка; в поле — начало / конец текста |
| **← →** | курсор в поле; в списке файлов — родительская / выбранная папка |

### Сети и поиск

**/** переводит фокус в поиск. Поиск учитывает SSID, BSSID, защиту и канал;
**Enter** возвращает к списку, **Esc** выходит из поля, сохраняя запрос.
Команда **Сбросить поиск** находится в F1. Обновление сохраняет выбранную сеть
по BSSID и не переводит фокус. **›** обозначает активную строку, **•** —
выбранную строку, когда ввод направлен в другую область.
**Tab / Shift+Tab** переключают только список и поиск.
**↑↓** и **Page Up / Page Down** переводят фокус из поиска в список и
перемещают выбранную сеть. **Home / End** в списке переходят к первой / последней.
Колесо мыши над списком прокручивает его по три строки; выбранная сеть остаётся
в видимой области. В заголовке показаны общее число сетей и видимый диапазон.
Колесо также работает в окне сохранённых захватов с платы.

### Параметры и файлы

Поля сгруппированы в данные и проверку. **Дополнительно → Enter** раскрывает
мутации, файл правил и BSSID; значения сохраняются при сворачивании.
**Начать подбор** закреплён над нижней строкой и достижим через Tab.
Причина недоступности запуска видна сразу, ошибки показаны возле полей.

**Enter** на поле с вариантами открывает выбор, на файловом поле — папки и файлы.
Путь можно напечатать или вставить; длинные пути показывают начало и конец.
В выборе файла **Enter / →** открывают папку или выбирают файл,
**← / Backspace** поднимаются выше, **Esc** возвращает к параметрам.
**← →**, **Home / End**, **Backspace / Delete** редактируют текст обычным образом.
Для полной очистки текущего поля есть **F1 → Очистить поле**: Ctrl-комбинации
установленной версии OpenTUI до приложения не доходят.

**F1 → Компоненты**, **Проверить компоненты**, **Установить компоненты** и
**Справка** доступны из формы. Выбор файла и справка сохраняют текст, курсор,
фокус и раскрытые настройки. В списке файлов **Backspace** поднимает на уровень выше.

### Выполнение и результат

**Tab** переключает журнал и остановку. **Esc** открывает подтверждение остановки.
После подтверждения видна **Остановка…**, пока процесс завершает работу.
Этапы имеют маркеры **[OK]**, **>>**, **[..]**, **[--]**: завершён, текущий,
ожидает, пропущен. Прогресс, скорость и ETA появляются при наличии данных.
Неизвестная длительность обозначается явно.

Ручная прокрутка переводит журнал в **паузу**, новые сообщения не сдвигают
просматриваемые строки. **End** возвращает к последним сообщениям и включает
**слежение**. На экране результата показан журнал именно этого запуска.

Пароли в результате и ключи сохранённых сетей скрыты. Используйте явное действие
**Показать пароль** или **Показать ключ**; повторное действие скрывает значение.
Возврат к параметрам сохраняет источник и параметры завершённого запуска.

## Возможности

* **Пассивный список сетей** (стартовый) — сигнал, BSSID, канал, шифрование.
  **↑ ↓** выбирают сеть, **Enter** открывает отчёт.
* **Экран проверки сети** — защита, источник данных и кнопка
  **Начать подбор** (**Enter**). Причина недоступности показана перед запуском.
* **Автоматическая лестница** (**Enter** на экране аудита) — ключ Windows, захват,
  кандидаты по имени и MAC, частые пароли, RockYou, мутации, цифры. Полный
  проход ≈ 42 минуты на 684,5 kH/s.
* **Экран «Сохранённые сети»** — ключи, которые Windows уже хранит для
  этого компьютера. Работает всегда: без прав администратора и без
  спецоборудования.
* **Ручной подбор** — свой словарь, маска, мутации, лимит.
  Действие **Файл** открывает выбор файла из любого места формы, само переключая
  «Источник» на файл, если поле захвата ещё не показано.
* **Справка** — зачем нужны данные WPA2, плюсы, минусы и ограничения.
* **Экран «Параметры»** — источник, метод, лимит и дополнительные настройки.
  Компоненты доступны через F1 и показаны сбоку на широком терминале;
  действие **Начать подбор** закреплено внизу.
* **Экран подбора** — цель, текущий этап лестницы, прогресс, скорость, ETA.
* **Экран результата** — пароль, через какой этап найден, и **что делать
  дальше**, если не найден: у каждой причины свой совет, а не один общий.
* Автоперезапуск с повышенными привилегий через UAC.

## Что работает прямо сейчас

Автоматический режим проверен целиком на настоящем hashcat и настоящем захвате
(`_test_auto.py`): фикстура `wpa2_psk_12345678.pcapng` прогоняется через весь
`pipeline.auto_attack`, и пароль `12345678` находится на **первом** этапе —
в сгенерированных кандидатах, за 2,2 с:

```
real ladder: '12345678' via EAPOL handshake · кандидаты по имени и MAC сети in 2.2s
```

Отдельный тест в том же файле требует обратного: подставной словарь, в котором
пароля нет, обязан дать честный «не найден», а не результат из potfile.

Полный ручной цикл подбора тоже проверен (`_test_e2e.py`, тот же пароль за ~3 с).

На этой машине читаются **8 сохранённых сетей, у 7 доступен ключ** — без единого
дополнительного файла и без прав администратора:

```
╭─ Профили ───────────────────────────────────────────────╮
│ [+] BruceNet            WPA2-Personal       CCMP   brucenet │
│ [+] Speedometer-Setup   WPA2-Personal       CCMP   12345678  │
│ [o] Rede Publica        Открыть             Нет    открытая  │
╰──────────────────────────────────────────────────────────╯
```

## Работа полностью из TUI

Запусти `python main.py`. Всё задаётся внутри интерфейса.

**Быстрый путь:** выделил сеть → **Enter** (отчёт) → **Enter** (подбор) →
результат. Всё остальное ниже нужно только когда автоматика не подошла.

**Ручной путь** — на экране отчёта открой меню стрелкой **→** или **F1**, выбери
**«Параметры»** стрелками и нажми **Enter**:

1. Выбранная в списке сеть подставится в параметры; форму можно открыть и без
   результатов сканирования.
2. В поле **Источник** выбери готовый файл или захват выбранной сети. Живой
   захват использует установленные компоненты и доступен при поддержке адаптера
   и нужных правах; причину недоступности форма покажет до запуска.
   Для выбранной сети форма сохраняет источник «Захват выбранной сети» даже
   при недоступном адаптере: она не подменяет его пустым файлом захвата.
3. Выбери поле «Захват» и нажми **Enter**;
   перейди по папкам и выбери
   `.pcap`, `.pcapng`, `.cap` или `.22000`. Путь также можно вставить в поле.
   **Откуда взять файл, если адаптер не умеет режим монитора**, — в справке
   (**F1 → Справка**), раздел «Откуда взять файл захвата».
4. **RockYou WPA** уже выбран по умолчанию. Через **← →** в поле **Подбор** можно
   выбрать быстрый список, свой словарь или маску.
5. Перейди к кнопке **Начать подбор** стрелками **↑↓** или **Tab** и нажми **Enter**.
   Если в файле несколько точек доступа, появится
   отдельный список выбора сети.

**Tab / Shift+Tab** переключают поля, **↑↓** — тоже; **Ctrl+U**
очищает поле целиком. Команда **F1 → Проверить** читает окружение и разбирает файл:
показывает, нашлись ли EAPOL или PMKID, и называет причину, если нет.
Кнопка **Скачать** ставит hashcat и словари.
Кнопка **Справка** открывает справку; **↑↓ / PgUp / PgDn**, **Enter** и
**Страница ±** её листают, **Esc** возвращает к параметрам без потери введённых
значений.

На главном экране **Enter** открывает отчёт по выбранной сети. На отчёте
**Enter** запускает подбор, **Esc** возвращает к списку. Кнопка **«Настройка»**
открывает объединённый экран параметров и проверки.

Готовые словари в `assets/`:

| Вариант | Размер |
|---|---|
| RockYou WPA | 9 609 471 кандидатов, около 100 МиБ; длина от 8 до 63 байт |
| Быстрый | 4800 частых WPA-паролей |

Источники — [RockYou в SecLists](https://github.com/danielmiessler/SecLists/blob/master/Passwords/Leaked-Databases/rockyou.txt.tar.gz)
и [Probable WPA в SecLists](https://github.com/danielmiessler/SecLists/blob/master/Passwords/WiFi-WPA/probable-v2-wpa-top4800.txt).
Контрольная сумма загруженного архива проверена по GitHub; сведения о словарях
сохранены в `assets/wordlists-info.json`.
Совпадение с одним из кандидатов не гарантируется: сильного уникального пароля
в готовом словаре может не быть.

### Почему одной выбранной сети недостаточно

SSID, BSSID и канал указывают цель, но не содержат данных для проверки пароля.
Эта программа проверяет кандидатов на компьютере по сообщениям WPA2 EAPOL
или PMKID, извлечённым из записи обмена. Сам пароль в записи открытым текстом
не хранится. [Формат данных hashcat](https://hashcat.net/wiki/doku.php?id=cracking_wpawpa2).

При живом захвате приложение создаёт такой файл автоматически. Источник
«Файл захвата» позволяет использовать уже готовую запись этой же сети,
например полученную на тестовом стенде с поддерживаемым адаптером.
Программа не проверяет каждый кандидат повторным подключением к роутеру.

| Метод | Плюс | Минус |
|---|---|---|
| Ключ Windows | Единственный способ со 100 % результатом | Работает только если этот компьютер подключался к сети |
| Кандидаты по имени и MAC | Закрывает заводские пароли роутеров за доли секунды | Узкий класс паролей |
| Быстрый словарь, 4800 | Короткая первая проверка | Маленький охват |
| RockYou WPA | Большой готовый набор | Дольше; случайного пароля может не быть |
| Свой словарь | Известный набор для эксперимента | Нужно подготовить список |
| Маска | Полный охват заданного формата при завершении | Пропускает другой формат; большой диапазон дорог |
| Мутации словаря | Типичные изменения слов | Больше вариантов и времени |
| Сохранённые сети | Быстро показывает уже сохранённый ключ | Это чтение профиля, а не подбор |

### Как распределяется время между этапами

`wifi_tool/auto.py` режет общий лимит на доли по стоимости этапа в кандидатах,
измеренной на этой же машине: hashcat печатает `Speed.#01`, программа его
разбирает и пересчитывает доли для оставшихся этапов. Неиспользованное время не
пропадает — оно целиком достаётся следующему этапу.

На RTX 4060 Ti (hashcat 7.1.2, mode 22000 — **684,5 kH/s**) при лимите 30 минут:

| Этап | Кандидатов | Нужно | Получает |
|---|---|---|---|
| кандидаты по имени и MAC | ~80 тыс. | 0,1 с | 8 с (минимум на старт hashcat) |
| частые пароли | 4 800 | 0,01 с | 8 с |
| RockYou WPA | 9,6 млн | 14 с | 12 с |
| RockYou + best66 | ~620 млн | 15 мин | 13 мин |
| цифры 8 | 100 млн | 2,4 мин | 2,3 мин |
| цифры 9 | 1 млрд | 24 мин | остаток |

Полный проход всех восьми этапов — около 42 минут. Маска из 10 цифр (~4 часа)
в лестницу не входит сознательно: на практике она почти никогда не выигрывает
у rockyou с мутациями за то же время. Добавить её можно через
`--runtime` и `--mask` вручную.

### Запуск приложения

```bash
python -m pip install opentui
python main.py
```

При первом запуске приложение попросит права администратора. Без них
сканирование всё равно работает (если включена геолокация Windows), но захват
невозможен. Автоматический режим в этом случае всё равно проверит сохранённые
ключи и честно скажет, что не хватает.

### Оффлайн-режим

Если захватывать рукопожатие нечем, можно разобрать уже готовый файл — права
администратора для этого не нужны:

```bash
python main.py --file path/to/capture.pcapng
```

Поддерживаются `.pcap`, `.pcapng` и уже готовые `.22000`-файлы. Приложение
откроет форму TUI с выбранным файлом; выбери поле запуска стрелками и нажми
**Enter**.

### Выбор кандидатов и лимита подбора

Автоматический режим без параметров — то же, что **Enter** на экране отчёта:

```bash
python main.py --auto
```

`--auto` нельзя сочетать с `--wordlist`, `--mask` или `--no-rules` — это два
описания одного прогона, и приложение скажет об этом, а не выберет молча.

Для аудита собственной WPA-Personal сети можно задать свой словарь:

```powershell
python main.py --file "capture.pcapng" --wordlist "my-passwords.txt" --no-rules --runtime 600
```

Или маску, когда известна часть пароля. Например, `MyHome?d?d` проверяет
два неизвестных цифровых символа после `MyHome`:

```powershell
python main.py --file "capture.pcapng" --mask "MyHome?d?d" --runtime 600
```

| Параметр | Значение |
|---|---|
| `--auto` | Автоматический режим без вопросов; то же, что **Enter** на экране аудита |
| `--wordlist PATH` | Собственный файл кандидатов; без параметра берётся словарь из `assets/` |
| `--mask MASK` | Фиксированная маска из 8–63 байт; `?d` — цифра, `?l` — строчная латинская буква, `?u` — заглавная, `?s` — спецсимвол, `?a` — печатный ASCII, `??` — буквальный вопросительный знак |
| `--rules PATH` | Файл мутаций словаря |
| `--no-rules` | Проверка словаря без мутаций |
| `--runtime SECONDS` | Положительный лимит времени; по умолчанию 600 секунд, включая подготовку hashcat |
| `--bssid AA:BB:CC:DD:EE:FF` | Одна целевая точка доступа в захвате |

Словарь и маска — отдельные режимы. Правила применяются только к словарю.
Если в захвате несколько точек доступа, приложение попросит указать `--bssid`;
на подбор передаются только записи выбранной точки доступа.

Во время работы показываются процент проверенных кандидатов, скорость и ETA.
`Esc` отменяет подбор; закрытие приложения также останавливает процесс подбора.
Исчерпание кандидатов, отмена, лимит времени и ошибка hashcat отображаются отдельно.
«Не найден» означает, что пароль не встретился среди проверенных кандидатов.

Параметры масок и статуса описаны в [документации hashcat](https://hashcat.net/wiki/?id=hashcat).
Проверка обоих режимов на готовой фикстуре: `python _test_e2e.py`.

## Захват рукопожатия — почему это отдельная задача

Windows обычно отдаёт программе обычные данные с заголовками Ethernet.
Для захвата кадров 802.11 из эфира нужны Npcap с поддержкой raw 802.11 и
подходящий адаптер/драйвер с режимом монитора. Само наличие Wireshark этого
не гарантирует. [Документация Wireshark](https://wiki.wireshark.org/CaptureSetup/WLAN).

**Последняя проверка на этом компьютере, 7 октября 2026:** обнаружен Intel AX211.
У Npcap поддержка raw 802.11 уже включена (`Dot11Support = 1`). Однако запрос
поддерживаемых режимов через `WlanHelper ... modes` возвращает только `managed`,
без `monitor`, а `tshark -I -L` не выдаёт типов кадров. Текущий драйвер не
предоставляет режим монитора; живой захват в этой конфигурации недоступен.

Если приложение сообщает, что raw 802.11 выключен, переустановите Npcap с
галочкой **Support raw 802.11 traffic (and monitor mode)**. Если raw 802.11 уже
включён, но доступен только `managed`, для живого захвата нужен другой
подходящий адаптер/драйвер. Приложение проверяет поддерживаемые режимы и типы
кадров; при отсутствии поддержки показывает причину в параметрах.
[Инструкция Npcap](https://npcap.com/guide/npcap-users-guide.html).

Для подбора по уже готовому файлу настройка Npcap и права администратора
не нужны: на экране отчёта открой меню **F1**, выбери
**«Параметры»** и подтверди **Enter**; затем нажми **Enter** на поле «Захват».
Кнопка **«Файл»** работает
из любого места формы и сама переключает «Источник» на файл, если поле захвата
ещё не показано. Запуск — **Начать подбор** на той же полосе.

### Откуда взять файл захвата

Если адаптер не умеет режим монитора, файл нужно получить иначе. Подходят
`.pcap`, `.pcapng`, `.cap` и `.22000`. Этот же список есть в справке программы
(**Справка** на полосе кнопок, раздел «Откуда взять файл захвата»), потому что
вопрос возникает ровно там, где адаптер не справился.

Для своей сети:

* **Wireshark** — поставить беспроводной адаптер в режим монитора, выбрать канал
  роутера, нажать Capture и переподключить своё устройство. В потоке появится
  рукопожатие EAPOL; сохранить как `.pcapng`.
* **tshark**, то же самое без графической программы:
  `tshark -i <интерфейс> -I <канал> -a duration:120 -w own.pcapng`
* **Анализатор handshake на телефоне** (например, Wifib на устройстве с root) —
  сохраняет файл, который потом выбирается кнопкой **«Файл»**.
* **Готовый `.22000`** выбирается напрямую, конвертер не нужен.

Проверить, что файл пригоден, можно кнопкой **«Проверить»**: она разбирает файл и
либо показывает, сколько EAPOL/PMKID нашлось, либо называет причину. В выборе
файла отфильтрованы по расширению, так `.exe` или `.txt` туда не попадут.

### Что это значит для автоматического режима

На этой конкретной машине шаг «захват» выполнить нельзя: драйвер Intel AX211 не
отдаёт режим монитора, и права администратора тоже не выданы. Поэтому на экране
аудита кнопка подбора показывает **ПОДБОР — ЗАКРОЙ БЛОКЕР** и объясняет, что
именно мешает; этап с сохранённым ключом при этом всё равно работает. Дальнейшие
этапы лестницы не запустятся вслепую: подбора без данных для проверки не бывает.

Чтобы этапы со второго по восьмой реально работали, нужно одно из двух:

* адаптер с поддержкой монитора (Alfa AW036ACH, MediaTek MT7612U и подобные) —
  обычный встроенный чип почти никогда не подходит;
* готовый файл захвата той же сети, полученный на стенде с подходящим адаптером
  (`.pcap` / `.pcapng` / `.22000`) — тогда **Параметры → Файл → НАЧАТЬ ПОДБОР**
  прогоняет всю лестницу целиком.

Со сменой адаптера менять ничего не нужно: приложение само определит доступный
инструмент захвата и режим монитора при следующем запуске.

### Принудительное переподключение (deauth)

Пассивный захват ловит рукопожатие только когда клиент **сам** решил
переподключиться. Это решение принадлежит клиенту — телефон проснулся, ноутбук
потерял сигнал, кто-то выключил-включил Wi-Fi — и в тихой сети это случается два
раза в день. Никакое увеличение окна тут не помогает: не хватает самого события.

Поэтому в параметрах, в разделе «Дополнительно» для живого захвата, есть
**«Отвалить клиентов»**. Это отправка кадра деаутентификации (`wifi_tool/deauth.py`):
25 байт со словами «я тебя не знаю» — то, что точка доступа сама шлёт клиенту,
которого не видит слишком долго. Клиент получает кадр и делает ровно то, что
сделал бы через несколько минут: переподключается. Рукопожатие попадает в
захват за секунды.

Решения, которые стоит знать:

* **выключено по умолчанию.** Эффект — на всех устройствах этой сети, не только
  на этой программе: на несколько секунд пропадает связь у всех. Поэтому это
  явная галочка, а не молчаливое поведение по умолчанию;
* **не мешает пассивному захвату.** Если инъекция недоступна (нет scapy, нет
  прав, адаптер не умеет) — в журнал идёт строка с причиной, захват продолжает
  работать как раньше;
* **форма формы проверяет это заранее.** Если галка стоит, а отвалить нечем —
  запуск блокируется с объяснением. Иначе пользователь смотрел бы на пассивные
  пять минут, веря, что кто-то его отвалил;
* **802.11w его отменяет.** Protected Management Frames — это как раз про то, что
  клиент игнорирует неаутентифицированные управляющие кадры. Там деаут не
  сработает, и это правильный ответ сети, а не ошибка программы;
* **кадры идут, пока идёт захват**, и останавливаются вместе с ним: деаут после
  конца захвата — это просто сеть, которую выключают впустую;
* **кадры уходят только после настройки канала.** Захват сначала переводит
  адаптер на канал цели, и лишь потом отпускает деаут: кадр на пустом канале не
  отвалит никого, а запуск выглядел бы как пассивный захват, которому не повезло.

Три проверки, без которых деаут врал бы в журнал:

* **режим монитора читается назад** после открытия handle'а. В managed-режиме
  драйвер отбрасывает управляющие кадры молча: отправка возвращает правдоподобное
  число, в логе «отправлено кадров: 45», и ни один кадр не вышел в эфир;
* **тип канала проверяется** (`datalink()`): на Ethernet-типе `pcap_inject`
  дописывает 14-байтный заголовок, и кадр в эфире получается битым, а отправка
  опять рапортует успех;
* **возвращаемое значение отправки проверяется**, а не засчитывается попытка.

Требуется `pip install scapy`, права администратора и адаптер с режимом монитора.
Скорость отправки — 3 кадра подряд каждые 4 секунды, до минуты: клиент, который
пропустил один кадр, просто не переподключится, и захват провалится по причинам,
выглядящим как невезение.

### Адаптер после захвата

Захват идёт на адаптере, переключённом в raw 802.11, и возвращает его в обычный
режим **только инструмент захвата своим кодом выхода**. Убитый процесс этот код не
выполняет — а у нас есть два штатных повода его убить: пользователь нажал Esc и
захват остановился раньше, чем рукопожатие уже оказалось в файле. Адаптер после
этого не сканирует: `netsh wlan show networks` возвращает пустоту без всякой
ошибки, интерфейс выглядит просто «отключённым», и оживает только после
переподключения по USB.

Поэтому `capturer.restore_managed_mode()` вызывается после **каждого** захвата
(`WlanHelper` из Npcap — он и переключал, `netsh` — если захват шёл другим
инструментом), а отказ возвращается строкой в журнал, а не исключением: захват
уже состоялся, и неудачная уборка не должна выбрасывать пойманное рукопожатие.

На случай адаптера, залипшего до этих правок (или после чужого инструмента) есть
ещё две страховки, обе проверяют более дешёвое объяснение раньше дорогого:

* пустой скан списка сетей → попытка вернуть режим и **повторный скан**
  (`pipeline.scan_networks`);
* `check_readiness` не нашёл адаптер → та же попытка и повторная проверка, и
  только потом «Wi-Fi адаптер не найден».

### Какой адаптер выбирается для захвата

Не тот, что netsh показывает первым. Ноутбук с USB-стиком — это два беспроводных
адаптера, и встроенный обычно стоит первым, а его драйвер режима монитора не
умеет вовсе. Выбор «первого» давал худшее из возможных сочетаний: программа
писала «драйвер не поддерживает режим монитора» про ноутбук, у которого рядом
воткнут рабочий адаптер, а стик — тот, который на самом деле ловит рукопожатия, —
не открывался вообще.

Теперь `pipeline._find_wireless_iface()` спрашивает каждый беспроводной интерфейс,
умеет ли он захват вообще (`capturer.monitor_capable()` → `WlanHelper … modes`),
и берёт первый умеющий. Обнаруженный адаптер по-прежнему предпочитается прочим,
так что машина с двумя хорошими адаптерами ведёт себя как раньше. Если умеющих
нет, возвращается первый кандидат — чтобы экран мог объяснить, *почему* не
получилось, а не просто констатировать отсутствие.

Два сопутствующих решения:

* адаптер, который сам netsh называет беспроводным, остаётся кандидатом даже если
  его имя ничего не говорит про Wi-Fi («Мой переименованный адаптер», «TP-Link_2.4»);
* «не знаю» не считается «не умеет»: если `WlanHelper` не ответил про режимы,
  интерфейс не вычеркивается — вердикт выносит `check_monitor_support()`, который
  действительно открывает радио.

### Канал, на котором идёт захват

Адаптер в режиме монитора слушает **тот канал, на котором его оставили**, а не тот,
который нужен. `netsh wlan show interfaces` на отключённом адаптере показывает
канал, на котором он замер после последнего подключения, — обычно это 1. Захват
сети на канале 6 при адаптере на канале 1 пишет в файл пять минут пустой полосы и
честно рапортует: «сети не переподключались».

Раньше канал доходил до `build_command`, где подставлялся в `{channel}`, — и
терялся там: **ни один из двух шаблонов бэкенда `{channel}` не содержит**. Ни
`-i <iface> -I -a duration:<n> -w <out>`, ни `-i <iface> -f <out>`. Молча, без
единого слова в журнале.

Теперь:

* если шаблон бэкенда содержит `{channel}` — канал ставит сам инструмент (это
  остаётся настраиваемым через `assets/capture.json`);
* иначе `capturer.set_monitor_channel()` переключает адаптер через `WlanHelper`
  и **читает значение обратно**, а не считает успех по коду возврата: отказ
  драйвера возвращает 0 и оставляет адаптер на прежнем канале;
* порядок соблюдается явно: канал ставится только в режиме монитора, поэтому
  захват стартует первым, а переключение ждёт `current_mode() == "monitor"`;
* 5 ГГц идут через `freq`, а не `channel`: у `WlanHelper` команда `channel`
  заканчивается на 14, то есть покрывает только 2.4 ГГц (канал 36 = 5180 МГц);
* если переключить нечем — в журнал идёт строка с обоими номерами каналов, а не
  тишина.

Сам отчёт о разнице виден пользователю:
`адаптер остался на channel=1 вместо 6 — сеть на канале 6, рукопожатий здесь не будет`.

## Архитектура

```
main.py                    точка входа + UAC-элевация
wifi_tool/
  scanner.py               netsh wlan show networks -> сети (локале-устойчиво)
  netsh.py                 единственная точка запуска netsh: блокировка + декодирование
  profiles.py              сохранённые профили: список и чтение ключа
  capturer.py              захват через cap80211 / tshark (подключаемые бэкенды)
  converter.py             выбор конвертера: wpawolf, иначе встроенный
  hc22000.py               встроенный pcap/pcapng -> hc22000 (чистый Python)
  auto.py                  автолестница: генерация кандидатов, деление бюджета
  cracker.py               асинхронная обёртка над hashcat -m 22000
  pipeline.py              оркестрация: захват -> конвертация -> подбор
  installer.py             скачивание внешних инструментов с проверкой SHA-256
  assets.py                поиск файлов, проверка прав администратора
  models.py                Network / CrackResult
  ui/                      state, controller, widgets, app, screens/
    actions.py             описания команд и имена клавиш
    commands.py            общий список команд и Ctrl+P / F1
    dialogs.py             поиск и выбор в модальных окнах
    navigation.py          история экранов и возврат с сохранением выбора
```

Поток данных: `scanner` → `capturer` → `converter` → `cracker`, каждый этап
вызывается из `pipeline.attack` (один настроенный прогон) или
`pipeline.auto_attack` (лестница целиком), а UI получает обновления через
`callbacks`.

Захват и конвертация вынесены в `pipeline.obtain_hashes`, потому что оба входа
должны вести себя одинаково: если захват расходится между ручным и
автоматическим режимами, «одна клавиша» перестаёт быть надёжной.

### Почему netsh запускается в одном месте

Два бага нашлись только при запуске на настоящей русской Windows 11, и оба
выглядели совершенно невинно.

**Подпись поля.** Реальный netsh пишет `Проверка подлинности`, а не
`Аутентификация`. Прежний список подписей содержал только вторую, поэтому у
каждой сети пустым оказывался `auth`, а вместе с ним `signal`, `channel` и
`Network.crackable`. Список сетей выглядел нормально — просто ни одна сеть не
считалась целью, и программа отказывалась работать с **любой** из них. Тестовый
пример был выдуманным и повторял ту же несуществующую подпись, поэтому проверка
проходила годами; теперь `_test_parser.py` использует дословный вывод netsh и
сверяется с живым сканированием.

**Кодировка.** netsh пишет UTF-8, пока он единственный процесс, работающий с
WLAN API. Стоит запустить второй — и он переключается на кодовую страницу
консоли (CP866). При декодировании как UTF-8 все кириллические подписи
превращаются в мусор, поля снова оказываются пустыми, а список сетей — снова
целым и снова бесполезным. Приложение при старте делает около десяти вызовов
netsh одновременно (адаптер, профили, сканирование), так что «работает, когда
один» — не то свойство, на которое можно положиться.

Поэтому `wifi_tool/netsh.py`: один замок на все вызовы netsh в процессе плюс
декодирование, которое выбирает кодировку по тому, в какой из них больше
кириллицы. Подписи полей и есть кириллица, поэтому правильность декодирования
измеряется напрямую, а не угадывается по BOM или локали.

### Автоматическая лестница

`wifi_tool/auto.py` — единственное место, где решается, что и в каком порядке
проверять:

* `candidates_for()` строит список из имени сети и MAC: сам SSID и его варианты,
  заводские пароли и учётные данные, SSID/MAC с цифрами от 0000 до 9999 и с
  годами, числовой хвост MAC. Всё, что короче 8 или длиннее 63 байт, отбрасывается
  на входе — такие строки не могут быть ключом WPA2 и только раздувают список.
* `Stage.candidates()` оценивает объём этапа: точно для масок и для
  сгенерированного списка, по размеру файла и числу правил — для словарей.
* `run_ladder()` платит этапам по порядку, отдаёт неиспользованное следующему
  этапу и останавливается на первом успехе.

Оценка скорости по умолчанию (`DEFAULT_HPS`) — измеренные на этой машине
684,5 kH/s. Как только hashcat печатает свою скорость, `auto.Rate` пересчитывает
доли для оставшихся этапов, поэтому лестница не рассчитана на конкретную видеокарту.

**Почему доли не пропорциональны.** Порядок лестницы — это ранжирование по
вероятности, и делить фиксированный бюджет пропорционально размеру этапа значит
это ранжирование игнорировать. Девять случайных цифр — это миллиард кандидатов и
сутки с половиной GPU; пропорционально они получали больше половины получаса, которого
им всё равно не хватает, а этап «RockYou + best66», которому не хватало минуты до
полного покрытия, обрывался на 71%. Теперь (`_plan_slices`) каждый этап получает
ровно столько, сколько нужно, по порядку; остаток забирает последний. На 30 минутах
полностью закрыты все этапы, кроме девяти цифр (49% вместо 7%); на 45 минутах
закрыта вся лестница.

**`MIN_STAGE_SECONDS` — не косметика.** hashcat тратит около 2,5 с только на
старт сессии, и доля в 0,1 с ушла бы целиком на инициализацию: этап отработал бы
вхолостую, а пользователь увидел бы «этап пройден» без единой проверки. Поэтому
любая доля не меньше 8 с — если только не осталось меньше.

### Вертикальный бюджет главного экрана

Главный экран состоит из четырёх блоков, и их высоты должны сходиться **точно**:
opentui не обрезает переполнение, а рисует поверх соседей. Поэтому всю вёрстку
решает одна функция `screens/scan.py::plan_layout()`, которая возвращает
единственный `Layout` (сколько строк баннера, сколько строк в панели деталей,
рисуется ли рамка кнопки, сколько строк занимает пояснение) — и рендерится он
и `ScanScreen`, и панель деталей.

Приоритет урезания, сверху вниз:

1. **список сетей** — гарантированные 4 строки (на очень низком терминале
   деградирует, см. `min_list_rows`), это часть потока;
2. **пояснение «захват невозможен»** — то, что останавливает заведомо
   бесполезную атаку;
3. **рамка кнопки ВЗЛОМАТЬ** — пока кнопка вообще нажимается; на заблокированной
   машине она не стоит трёх строк, и место отдаётся пояснению;
4. **строки баннера** (права админа объясняют, почему кнопка серая);
5. **информационные строки панели деталей** — вплоть до двух обязательных:
   имя сети и вердикт «можно подбирать».

### Грабли opentui, на которые здесь наступили

* **`@component` добавляет обёртку `Mount`**, которая не наследует
  `flex_shrink=0` внутреннего бокса. Yoga сжимала её ниже нужного, содержимое
  рисовалось поверх футера, и кнопка **ВЗЛОМАТЬ** исчезала. Строка сети и панель
  деталей поэтому — обычные функции, а не компоненты: `_network_row`,
  `_detail_panel`.
* **Пустой `Text` и `Span`, начинающийся с пробела, выпадают из `Row`** —
  разделители делаются через `NBSP`.
* **`Text` обрезает справа** (`rstrip`), поэтому `ljust()` не выравнивает
  колонки; выравнивание — только через фиксированную ширину (`widgets.col`).
* **`background_color` на строке внутри `For`** заставляет opentui переиспользовать
  покрашенный бокс для следующей строки: короткий SSID наезжал на соседнюю
  колонку. Выделение строки — только маркером `▸` и жирным текстом.

## Конвертация захвата

`hcxpcapngtool` из [ZerBea/hcxtools](https://github.com/ZerBea/hcxtools) на
Windows **не поддерживается** — это прямо написано в его README. Поэтому:

1. **Основной путь** — [WPAWolf](https://github.com/StrongWind1/WPAWolf),
   переписывание `hcxpcapngtool` на Rust с готовыми Windows-сборками
   (Apache-2.0). Ставится автоматически. Флаг `--smart` выбран намеренно:
   upstream прямо предупреждает, что `--strict` **теряет тысячи crackable
   MIC**, а `--smart` — reduction-опция, которая хэши не отбрасывает.
2. **Запасной путь** — `wifi_tool/hc22000.py`, конвертер без зависимостей.

Ветка с `wpawolf` включается только если бинарник найден; при его ошибке
автоматически включается встроенный конвертер.

## Обновление интерфейса

Ввод Windows читается в отдельном потоке. Отпускание клавиши, изменение окна и
события фокуса не останавливают отрисовку: обработчик UI забирает только готовые
байты. Анимация использует один снимаемый callback, а время — монотонные часы.

Регрессионная проверка в настоящем терминале Windows:

```powershell
python -X utf8 _test_ui_runtime.py --windows-probe "$env:TEMP\wifi-ui-runtime.json"
```

Она добавляет событие отпускания клавиши, ждёт кадры без ввода, затем проверяет
стрелку, кириллицу, вставку и завершение потока чтения.

`_test_ui.py` отдельно проверяет экран аудита на 10 размерах терминала от
44×16 до 120×40: кнопка подбора, имя сети и начало блокера обязаны выжить при
любом размере, ни одна строка не шире терминала, ничего не выше его высоты.
Именно эти проверки ловят ситуацию, когда тело панели на строку длиннее
доступного места — opentui тогда не обрезает, а затирает соседей, и кнопка
исчезает.

`_test_auto.py` проверяет автоматический режим целиком. Кандидаты, оценка объёма
этапов, деление бюджета, передача неиспользованного времени, пол развёртки,
отмена и разбор скорости hashcat — на подставных этапах, без подмены hashcat.
Два последних теста запускают **настоящий hashcat** по хэш-файлу, который
произвёл конвертер этого проекта:

* пароль `12345678` обязан найтись на **первом** этапе, сгенерированном из имени
  сети и MAC фикстуры — это проверяет и генератор кандидатов, и порядок этапов;
* подставной словарь без этого пароля обязан дать честный «не найден» — каждый
  тест использует отдельный пустой potfile, чтобы закэшированный ранее ответ
  не превратил промах в ложную удачу.

`_test_e2e.py` — главный тест. Он запускает **настоящий hashcat** по хэш-файлу,
который произвёл конвертер этого проекта, и требует, чтобы пароль
`12345678` (задокументирован в имени фикстуры) был восстановлен:

```
converted: 2 EAPOL record(s)
cracked : True password='12345678' in 4.2s
PASSWORD RECOVERED: 12345678
```

Ничего не подменяется: если вёрстка hc22000, кодирование полей, выбор nonce или
код message-pair неверны, hashcat либо не разберёт файл, либо не найдёт пароль.

`_test_groundtruth.py` дополнительно требует **побайтово совпадающий** вывод с
wpawolf на реальных захватах.

`_test_ui.py` проверяет не только наличие текста, но и то, что **экран помещается
в терминал**: ни одна строка не длиннее ширины, футер не вытеснен вниз, а список
сетей сохраняет гарантированное число строк. Это оказалось важнее, чем
кажется: opentui не обрезает переполнение, а рисует поверх, и лишняя строка
банера или панели деталей молча затирала кнопку **ВЗЛОМАТЬ**.

Фикстуры лежат в `tests/fixtures/` (не в git, скачиваются скриптом при первом
запуске теста, если их нет).

## Что пришлось учесть в формате hc22000

Всё ниже проверено побайтово против вывода wpawolf на реальном захвате:

* **Frame Control**: биты 0–1 версия протокола, 2–3 тип, 4–7 подтип
  (`QoS Data` = `0x88`, а не `0x22`).
* **LLC/SNAP**: ethertype EAPOL — `0x888E`, то есть байты `88 8e`.
* **EAPOL-Key**: фиксированная часть **95 байт**; nonce по смещению 13,
  **MIC по смещению 77**, длина key data по 93, key data по 95.
* **Replay counter** — big endian, как и остальные поля EAPOL.
* **Кодирование полей**: MAC-адреса и ESSID — hex **без разделителей**;
  hashcat mode 22000 ждёт именно hex.
* **Поле nonce** — это **ANonce** точки доступа, а не nonce самого
  экспортируемого сообщения. hashcat перевыводит PTK из ESSID, двух MAC и
  этого nonce; если подставить SNonce, PTK не сойдётся и подбор всегда
  провалится.
* **MESSAGEPAIR** — тоже hex: `82` = M2+M3 с телом из M2, `13` = с телом из M3,
  `80` = M1+M2 (challenge).
* **Проверка replay counter** (как у hcxpcapngtool по умолчанию): M1 и M2 делят
  счётчик, M3 инкрементирует его. Ретрансмиты и «мусорные» сообщения отбрасываются.

## Ограничения

* Захват требует драйвера, умеющего raw 802.11 (cap80211 или Npcap). Встроенный
  адаптер Intel AX211 монитор-режим поддерживает не всегда.
* Для WPA3/SAE переходов EAPOL может быть зашифрован — извлекается не всё.
* Встроенный конвертер не делает проверку мусорных шаблонов, которую делает
  wpawolf, поэтому на некоторых захватах выдаёт лишние (не ломающие) записи.
  Основной конвертер — wpawolf.
